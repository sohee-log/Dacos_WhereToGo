## 🔴 C-1 Render 재배포 — 이걸 안 누르면 어제오늘 고친 게 화면에 안 나온다

PR #43~#47이 `main`에 머지된 지 한 시간이 넘었는데 **배포본은 아직 옛 빌드**다.
`render.yaml`에 `autoDeploy: true`가 있지만 **대시보드 설정이 우선**한다.

**Render 대시보드 → `wheretogo-api` → Manual Deploy → Deploy latest commit**
(자동 배포가 꺼져 있으면 Settings → Build & Deploy → Auto-Deploy를 Yes로)

### 배포됐는지 확인하는 법

추천을 한 번 부르고 `score`를 본다. `?debug=1`이면 화면에서 바로 보인다.

| | 카드 순서 | 응답 시간 |
|---|---|---|
| **옛 빌드** | 1번 0.8603 · 4번 0.8808 — **점수 순이 아니다** | 약 3.3초 |
| **새 빌드** | 점수 내림차순 | 1초 안팎 |

### 배포되면 무엇이 달라지나

1. **1번 카드가 실제로 점수 1위가 된다.** 지금은 LLM이 돌려준 순서가 그대로
   화면에 실려 있어서, `?debug=1`을 켜면 4번 카드 점수가 더 높다. 심사위원이
   디버그 화면을 보면 바로 지적할 자리다.
2. **응답이 3.3초 → 1초 안팎.** DB 왕복 횟수를 10회에서 6회로 줄였다.

**화면 코드는 고칠 게 없다.** `results` 배열 순서만 바뀐다.

## 🟡 C-2 리허설 2회 — M8의 마지막 칸

**실제 배포본으로** 두 번 돈다. 아래를 눈으로 확인한다.

```
□ 온보딩 5문항 → 인원 → 추천 → 카드 클릭 → 별점까지 끊김 없이
□ ?debug=1 에서 1번 카드의 score가 가장 높다              ← 새 빌드 확인
□ 같은 좌표로 시각만 바꿔 결과가 실제로 달라진다           ← 차별점 시연
□ 이태원/용산역 카드에는 live_segment·crowd 가 숫자로 뜬다
□ 후암/이촌/청파 카드에는 그 두 키가 아예 없다 (0으로 그리지 않는다)
□ 첫 요청이 콜드스타트여도 안내 문구가 뜬다
```

**세 번째 줄이 이 프로젝트의 시연 포인트다.** 같은 자리에서 13시와 19시를 넣어
결과가 바뀌는 것을 보여주는 것이 "지금의 상황에 맞는 추천"의 증거다.
네·다섯 번째 줄은 `scenarios.md`가 경고한, 가장 틀리기 쉬운 자리다.
